- [ ] HTML syntax support in label text contents:
  - [x] We'll add a new field for specifying the brackets used for html syntax `html_brackets` — cascading job -> plate -> label -> line, and in job-config.json, defaulting to `<>`. `html_brackets` is a two-character string, the first of which specifies the left bracket, and the second the right bracket. This way, if a label contains chevrons, we don't need to worry about it being incorrectly recognized as html syntax. There's no need to specify a similar new field to specify the slash character, because we only look for the slash when it's enclosed by the html brackets (and whatever command was used), and when that follows the opening html enclosure to define a region of html-modified text. That is, not every forward-slash is taken to be part of html syntax, only those that occur in e.g. `</i>`.
