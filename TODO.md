- [x] Add a new optional bool field, `auto_descending_character_adjustment`, cascading job -> plate -> label (not to line). If true, then the system will automatically apply a combination of vertical downscaling and vertical raising to descending characters *that are (close to) colliding with characters on the following line. Also add to job-config, default `true`.
  - Implemented as a render-time mechanism in `label_renderer._render_positioned_lines`, with the math in the new matplotlib-free `plt_optimizer/generate/descender_adjust.py` (Win7/3.8 import guarantee). Four cascading fields on `LabelAttributes` + `PlateSpec` parity (label -> job -> config, never text lines, plate = parity-only like `use_baseline_spacing`): `auto_descending_character_adjustment` (default `true`), `descending_character_v_scale` (`[0.2, 1.0]`, `0.5`), `descending_character_raise` (`[0.0, 1.0]`, `0.7` = fraction of the glyph's **own descender depth**, so `1.0` lands its lowest point exactly on the baseline) and a fourth field `descending_character_clearance` (`ge=0.0`, `0.0` = a **unitless factor of the stroke floor**: the required gap is `floor * (1 + clearance)`, so the demanded air scales with the cutter width and reads the same at every text size). All four ship in `job-config.json` and are not required-when-unconfigured.
  - **Trigger is per glyph pair, measured against the following line**: a glyph whose ink hangs below its baseline, and a glyph on the line below whose X spans overlap it, whose vertical gap falls below `0.5 * (cutter_upper + cutter_lower) * (1 + descending_character_clearance)` (the engraved-stroke floor scaled by the unitless clearance factor; the floor is the same stroke-aware basis the text-hole system uses). `geometry.aabb_vertical_gap` measures the gap over the overlapping X span (`inf` when X-disjoint). A descender with no close partner below engraves exactly as rendered -- never a blanket adjustment, never keyed off the following line's cap line.
  - **Single proportional ramp** `t in [0,1]` drives both allowances together (`scale_y = 1 - t*(1 - v_scale)`, `raise = t * raise_fraction * descender`), scaled about the glyph's own baseline. The glyph's bottom is `raise(t) - descender*scale_y(t)`, so the gap it produces is linear in `t` and the smallest clearing `t` has a closed form (no bisection). The relief is one-way (a glyph only gets smaller and higher), so the fixpoint converges; each pass rebuilds the line from the **original** render at the glyph's full ramp, so ramps never compound.
  - **Exhausted allowances grow the inter-line spacing** (`_grow_spacings`, bisection on the stacked block height, capped by the vertical margins); a pair that neither the allowances nor all admissible spacing can clear raises `LabelRenderError` (non-zero CLI exit) naming both lines, the shortfall and the spent allowances.
  - Runs between the X phase (compression + alignment) and the Y phase (stacking) of the shared render core -- the relief is Y-only and the X phase X-only, so they commute, and X must run first because the pair gaps need final X positions. Works in both stacking modes. New `TextBlock.scale_y()` mirrors `compress_x` (arcs flatten at the chord tolerance, DEBUG log; stroke count preserved 1:1 so `glyph_groups` and the intra-chunk glyph sweep stay valid) and `TextBlock.replaced_strokes()` splices one glyph back at its original indices.
