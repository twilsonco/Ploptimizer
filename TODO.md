- [x] Extend descending character relief support to include adjusting descending characters in order to accommodate label bottom borders. No new fields/parameters are necessary for this.
  - Implemented as a **virtual "following line"**: `_border_box` (label_renderer) feeds the border's centreline into the existing rolling-circle machinery (`measure_glyph_gaps` + `ramp_for_measured` + `ramp_ink` + `InkGrid`), so no new measurement code and no new fields. The border rectangle is drawn at the label edge (`vp.rect(0, 0, width, height)`, no inset) and cut by the boundary/hole tool, so its centreline sits at `-height / 2` in the relief's stacked frame (the frame centres the ink block on `y = 0` at label `height / 2` -- the same constant in both stacking modes), and the required clearance is `required_gap(text_cutter, label.hole_cutter_diameter, descending_character_clearance)`. `hole_cutter_diameter` is already on `ResolvedLabel`, so no threading was needed.
  - **Every line is measured** (not just the last), so a single-line label -- which has no inter-line gap at all -- still triggers.
  - **Crossing `v_margin` is not a collision**: the trigger is measured purely against the border centreline and the relief never reads `v_margin`. Ink spilling into the margin is accepted behaviour (the margin clamp's zero-spacing overflow case already does this); only the border stroke matters. Pinned by the `margin_cross` label.
  - **Spacing growth is deliberately excluded** for border deficits: growing the gap above the last line moves that line **down** in the centred frame (`_baseline_table`'s `shift = (top + bottom) / 2`), which *deepens* a border collision. The per-glyph ramp (downscale about the baseline + raise) is the only lever. Pinned by the `spacing_untouched` label.
  - **Exhausted ramp at the border => WARNING, never an abort** (`_log_border_shortfalls`): the engraving is the best the allowances allow, so the job proceeds. Every glyph that ever triggered against the border is re-measured on the final geometry (`border_triggered`), so a glyph whose allowances could not move it at all (ramp 0) is not silently colliding. Shortfalls are gated at `_BORDER_SHORTFALL_TOLERANCE` (one plotter unit): the border ramp converges asymptotically (relieving a glyph shrinks the block's bottom extent, re-centring the block downward and undoing part of the relief), leaving a sub-unit residual that cannot exist in the emitted geometry. Border deficits never enter `relief.residual`.
  - **Fixed a latent under-application bug found on the way**: `propose_ramp` bisects the glyph's *current* (already-relieved) ink, so it returns the ramp still needed *on top of* the one the glyph carries; it now converts that increment to a **total** (`min(1, current + increment)`) because `_apply_glyph_ramps` rebuilds from the ORIGINAL render at the glyph's total ramp. Storing the bare increment under-applied the relief -- line-to-line hid that behind spacing growth, the border has no growth lever so it engraved short of the clearance.

- [x] Extend descending character relief support so that instead of the descending character doing all the adjustment, they would-be colliding characters on the following line also contribute to the adjustment, distributing the necessary vertical relief between both lines. Characters on the following line would only adjust by vertical downscaling, such that their lowest point doesn't move; they're downscaled vertically from the top down. Would need one new  float field, `descending_character_reciprocal_scale` — cascading job -> plate -> label -> line, and in job-config.json with default 0.5 — that determines the maximum amount of downscaling allowed for the characters on the following line. Their adjustment would happen in proportion to the scaling/raising of the descending character.
  - Implemented as a **shared ramp**: the same `t ∈ [0, 1]` that drives the descending glyph's downscale/raise drives every colliding partner on the following line as a **top-down scale about its own lowest ink point** — `y' = y_min + (y - y_min) * s_l`, `s_l = 1 - t * (1 - descending_character_reciprocal_scale)` — so the partner's bottom never moves and its top descends toward it. The composition reuses the existing primitives (`translate(0, -y_min) → scaled_y(s_l) → translate(0, y_min)`), no new `TextBlock` method; the measurement mirror is `descender_adjust.recip_ink` (= `ramp_ink` with zero raise). Cascade matches the sibling fields: job → plate → label (plate = schema parity; the relief is a property of the stacked block, never one line), `[0.2, 1.0]`, code default 0.5, `1.0` = the reciprocal half off (bit-identical to the historical one-sided relief).
  - **Partner scope:** every following-line glyph whose ink is within the required clearance of the descending glyph's sub-baseline ink (`descender_adjust.colliding_partners`, the same rolling-circle test as the trigger). The bisection keeps the frozen `InkGrid` over the lower line's **static** ink and measures the moving partners directly per candidate ramp with `geometry.ink_gap` — the grid is never rebuilt per bisection step.
  - **Monotonicity:** anchoring at the partner's lowest ink means a reciprocal fix never moves ink *down* past it, so the gap above the line widens monotonically and the **bottom border is untouched** (`descender_border_job.yaml` stays bit-identical). A middle-line glyph can carry both ramps (its own descending ramp into the gap below + a top-down ramp from the gap above): the upper ramp is applied first, then the reciprocal about the resulting lowest point; the existing fixpoint re-measures each pass and converges (ramps one-way ≤ 1.0, spacings one-way ≤ inner height).
  - `ramp_for` (box-model closed form) gained the reciprocal slope term `lower_height * (1 - reciprocal_scale)` as optional parameters — defaults reproduce the old form bit-identically. `DescenderFix` gained `reciprocal: bool = False`; reciprocal records carry `raise_amount = 0.0` and ride the existing `descender_adjustments_by_line`, so no new `RenderedLabel` field; the layout report prints them as `glyph 'i' shares relief, top-down scale 0.875 (gap 0.094in -> 0.281in)`.
